# 8.4.0（v15b + v15c）· 性能批 + 大文件夹落位修复

> 用户两次要求（2026-10-27 / 10-28）：**提高软件运行性能**、**再次全局迭代优化性能 修复BUG**。
>
> 没凭感觉调：先建可复现基准（`tools/perf_probe.py`），profile 定位，再改；
> 修复也都有失败测试先行（红→绿）。

## 一、性能：把"热路径当冷路径"的地方逐个拔掉

### 1. 启动：导入按需（−50ms）

冷启动 `import main` 实测 582ms，其中 `src.settings_dialog`（连带 `src.updater` →
`requests`/SSL 一整条链）**131ms**、`src.add_apps_dialog` **63ms** —— 而启动路径上
**没有任何一处**需要它们，只有用户真的点"设置 / 添加应用"才需要。

改成函数内按需导入（冻结包照样打得进去：PyInstaller 扫 import 语句，不看层级）。

### 2. 启动：`set_dock` 不再把 100+ 图标重建一遍（−55ms）

`main.py` 的顺序是"先 show 窗口，再 `set_dock`"，而 `set_dock` 调的是 `refresh_grid()`
——它把布局签名打成哨兵值，**无条件重建全部图标**。可网格的扣减入口 `_dock_inset()`
只读 storage，首次构建就已经把条带算进去了：这次重建纯属白做。

现在走 `_update_grid_metrics()`（几何真变了才重建），组件层也只在网格变化时重排。
配套把 `seed_from_layout()` 提到建窗口之前——Dock 条带厚度随条目数变化，
先填再建，首次网格就是最终几何。

| | 修前 | 修后 |
|---|---|---|
| `set_dock`（启动路径） | **63.6ms** | **7–10ms** |

### 3. 首帧：壁纸饱和度烘焙落盘缓存（冷 89ms → 热 6ms）

液态玻璃的"饱和度 140%"要把壁纸磨砂底图烘一遍。profile 显示首次 **64–89ms**，
其中 PIL 的 `import` 就占 ~40ms——而这结果**只跟壁纸内容有关**，壁纸不变时每次启动
都算出完全一样的一张图。

现在按（壁纸稳定版本 + 尺寸 + 百分比）缓存到 `%APPDATA%/…/cache/sat_*.bin`（原始
ARGB32，约 3.5MB），命中时**连 PIL 都不导入**。只保留最近 3 份（换壁纸不会越积越多）；
半截/损坏文件当作未命中，自动重算。

> `Wallpaper.version` 用的是 Python `hash()`（每次进程都变），不能当磁盘键——
> 新增跨进程稳定的 `stable_version`（crc32），并把它写进缓存文件名。

### 4. 翻页：视图动画不复算布局（v15b，−30ms/帧）

- 翻页期间"落定格点/所属页"按条目缓存（`_flip_bases`），逐帧只做加法；
  旧实现每帧每个图标重算 `_entry_pos`/`entry_page`/`find_entry`，30 帧共 **3090 次
  `winreg.OpenKey`**（全从 `resolved_icon_fit → native_icon_size` 漏出）；
- `native_icon_size` 加 1.5s TTL（值只可能因用户拖 explorer 图标大小滑条而变）；
- 折射加 `LiveLens.pixmap(follow_move=)`：整页同速平移期间复用贴图，落定后自动按新位置
  重算一次（4 个液态表面 × 30 帧 = 120 次重算 → 1 次）。

| | 修前 | 修后 |
|---|---|---|
| 翻页单帧（104 图标滑动） | **42.0ms** / 峰值 46.1 | **10–13ms** / 峰值 15–18 |
| 启动（窗口构建 + 首帧） | **382ms** | **164–240ms**（机器噪声内） |

## 二、修复：大文件夹（2×2 瓷砖）的落位全是"只算一格"

审核报告 P2-3 写的是"大文件夹拖到页底会跨页"，实测比这更宽——**所有落位入口都只把
瓷砖当 1 格**：

| 场景 | 旧行为 |
|---|---|
| 拖到**最后一列** | `big_extra_cells()` 贴边直接返回 `None`，右侧与下行三格**不登记占用**：瓷砖压着别人、别人也压着瓷砖 |
| 拖到**页底行** | 派生格落到下一页（页 = `row // rows_per_page`），2×2 被页边界切成两半 |
| 拖到**别人头上** | `_free_moves()` 只看主格，2×2 内其余三格的图标原地不动，落位后叠在瓷砖底下（看不见也点不到） |
| **多选整块**里含瓷砖 | `multi_move` 把它当 1 格平移：贴右/页底出界，派生格上的非选中图标不参与让位 |
| **重新扫描 / 整理布局** | `compact_layout` 完全不知道 2×2：新文件被补进瓷砖底下；`tidy/pack` 的派生格登记不检查是否已被组件占、也不检查页底 |

修法（同一套语义，四处共用）：

- `grid_flow.clamp_big_cell(cell, cols, page_rows)`：把落点夹进网格与**落点所在页**，
  贴边整体内移、形状守恒；放不下（只有 1 列 / 页高不足 2 行）时退到起点，绝不抛异常；
- `clamp_big_target(storage, entry, cell)`：非瓷砖 / 无界模式原样返回；
- 拖动预览、松手提交、红框**共用** `_drag_cell()` 的夹紧结果——预览与落点不会漂移；
- `_free_moves`：2×2 内被压住的图标用 `displace_cells()` 让开（页内就近、同行优先、
  互不重复），不再叠在瓷砖下；
- `multi_move`：边界按**真实 footprint**（右/下各多一格）计算，派生格进 `occupied`，
  被压住的非选中图标同样让位；
- `Storage.compact_layout / tidy_layout / pack_layout`：2×2 整块参与占格判定，
  `_big_block_used()` 检查派生格是否已被组件/Dock 禁放格占用，并拒绝跨页；
- 拖动中的红框按条目真实占位画（瓷砖 2×2，不再是 1 格）。

## 三、顺手修掉的真 bug

`rebuild()` 构造图标时**漏传 `big=`**（`_add_icon()` 传了）。后果：每次重建
（启动 / 改分辨率 / 切模式 / 导入配置）大文件夹都掉回 1×1 渲染，而布局仍是 2×2——
瓷砖占四个格，里面只画 4 个成员。重开一次就复现。

## 判据

- 新增 `tests/test_big_folder_bounds.py` **24 项**：夹紧纯函数（右/下/第二页/双轴/1 列
  兜底）、`_free_moves` 夹到网格内且同页、块内图标被挪出、落位后**格子唯一 + 四格同页**、
  `_drag_cell` 与提交同源、多选含瓷砖无重叠、compact/tidy 整份布局无重叠且不跨页；
- 新增 `tests/test_wallpaper_cache.py` **11 项**：稳定版本、冷写热读逐字节相等、
  **子进程验证命中时不导入 PIL**、百分比进 key、伪快照不落盘、损坏缓存当未命中、
  只保留最近 N 份；
- 新增 `tests/test_perf_batch.py` 15 项（v15b）：TTL、翻页基准只算一次且帧位置逐像素
  等于"落定 + flip_px"、`follow_move` 四种情形、`rebuild` 后仍 2×2；
- 全量 **116/116** + smoke，`check_docs` ERROR 0。

## 已知遗留（没动，写明白）

- **首次绘制每个图标 ~1.6ms** 是 Shell 图标提取的一次性成本（104 个 ≈ 166ms，占了启动的
  大头）。要再快得放后台线程 + 占位图，涉及 COM 单元线程，风险比收益大；
- 文件夹弹窗开启 7–26ms 是一次性成本，不值得为它加缓存复杂度；
- 360 解压项 InvokeCommand 无声失败（P2-1，有自带解压兜底）、BandGuard widget 侧
  untrack 待核（P2-6）。

## 升级提示

- 无配置迁移；首次升级后第一次启动仍会烘一次饱和度（生成缓存），之后每次启动省 ~60ms；
- 大文件夹现在**不会被拖到页边被切开**：贴页底会整块上移一格、贴右列会整块左移一格；
- 若历史布局里已有"图标压在瓷砖底下"的脏数据，下一次"重新扫描桌面 / 整理布局"
  会把它们挪出来。
