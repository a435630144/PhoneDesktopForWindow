# 8.3.3（v14z）· 多选拖动整块跟手（不再只有手底下那个跟鼠标）

> 用户反馈（2026-10-27）：框选多个图标拖动时，**只有当前 hover 的图标跟随鼠标瞬间移动**，
> 其余框选的图标也在动，但"动画之后，不连贯"。

## 根因：两套位置源

- 手底下那个图标走的是**浮动拖影**（`_DragGhost`），每一帧按鼠标位置平移，1:1 跟手；
- 其余成员走的是**按格预览 + 280ms 弹簧**（`animate_to`）：指针跨过一格才重算一次目标，
  每次刚起播就被下一格的目标打断。

dragMove 的频率远高于 280ms，所以成员永远在"追赶"——块看起来是散的，松手才归位。

## 修法：整块一个刚体

拖动期间成员位置 = **按下瞬间的位置 + 指针位移**，与拖影共用同一个 `gpos` 序列
（`AppIcon.drag_delta()`），并按与布局同一份页边界（`grid_flow.page_rows_of`）夹紧：
贴边时整块停住，不会"视觉飞出页外、松手又弹回"。

配套三点：

1. **不叠让位弹簧**：预览落地时只给被让位的非选中图标播动画，成员不再受第二套位置源拉扯
   （两套位置源互相打架正是"不连贯"的来源）；
2. **跟随由拖拽源信号驱动**（`dragMoved`），不是桌面窗口的 `dragMoveEvent`——指针压在
   **别的图标**上时，合成事件发给那个图标，桌面窗口收不到，整块会冻住而拖影继续走；
3. **命中测试排除"自己人"**：成员跟手后永远压在拖影底下，若不排除，`_hitTarget` 会一直
   命中成员（让位预览直接死，松手还可能把整块拖进自己）。

## 判据

新增 `tests/test_multi_follow.py` 14 项：基准记录、`drag_delta`、逐像素等式（非整格位移
37/-23）、主条目自身不动、右/下越界夹紧、同一格内微动也跟手、成员不叠弹簧、
信号驱动、翻页后自动退回按格预览、"不排除会命中自己人"的反证。

## 升级提示

- 无配置迁移；拖动手感为纯交互改动。
- 拖动中翻页仍可用：翻页后整块改由翻页系统统一平移（像素跟随自动让位）。
