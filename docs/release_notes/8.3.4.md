# 8.3.4（v15a）· 重命名输入框重做 + 字号放大不再切掉第二行

> 用户反馈（2026-10-27）：**文件夹重命名的文本框有点丑，点击出现的文本框会超出 UI**；
> **图标字号调大时，第二行文字被 hover 框裁剪**。

两个都是"边界算错"，不是观感口味问题。

## 一、重命名输入框：从"贴上去的系统框"变成标题就地可编辑

旧实现是一个固定 **240×36** 的 `QLineEdit`，居中在文件夹标题带上。而标题带右侧要让给
三个按钮（关闭 / 添加 / 换色）共 86px——**240px 宽的弹窗（最小宽度）只有 126px 标题带**，
居中的 240px 框左右各顶出 40+px，直接压在弹窗外的壁纸上。所谓"超出 UI"就是这个。

现在的做法：

- **尺寸跟锚点走**：`BandInputBox.show_over(标题带, bounds=弹窗矩形)` 把输入框铺在标题带上，
  宽度取标题带宽（120~360），高度比标题带高 4px（28~40），再夹进弹窗矩形与可用屏幕，
  外阴影也留 4px 余量——**任何尺寸的文件夹都不会越界**；
- **自绘玻璃面**：深色圆角底 + 顶部 1px 内高光 + 强调色描边（聚焦亮、失焦转白 46）+ 两圈
  柔和外阴影，文字居中、与文件夹标题同族加粗。不再是"系统边框 + QSS 圆角"两层互相打架；
- **标题让位**：编辑期间弹窗不画标题，不会出现"原文 + 输入框"两份文字；
- **选中态收敛**：半透明强调色（alpha 80）+ 白字，代替原来把名字糊成一条蓝带的实心高亮。

## 二、字号放大后的第二行：布局终于知道有"字号缩放"

图标标签的绘制字号 = 基准字号 × `label_font_scale`（70~140%），但**布局预留的标签带高度
一直按 100% 算**（`grid_sizing.label_height()` 不知道有这个旋钮）。于是：

| 字号 | 旧行为 |
|---|---|
| 120% | 仍按"预留了两行"硬画两行 → 第二行越过部件底边，被 QWidget 自身矩形裁掉（hover 高亮框正好画在同一条边界上，看着就是"被 hover 框切了"） |
| 140% | 预留高度不够两行 → 悄悄塌成一行 |

修法（单一真相源）：

- `grid_sizing.label_height(box, lines, font_scale)` / `icon_layout(..., font_scale=…)`：
  标签带按**缩放后**的字号预留，且硬夹在格子高度内（`widget_h <= ch`，字号再大也不压下一行）；
- 缩放函数只有一处：`grid_sizing.scaled_font_px()`，布局与 `AppIcon._scale_font_px` 共用；
- `AppIcon` 画标签时按**实际可用高度**决定行数（`_fit_label_lines`），整块垂直居中——
  宁可少一行也绝不画到部件外面；
- 字号一变，桌面窗口 `apply_label_style()` 给每个图标**换一份 layout**（`setFixedSize` +
  重新居中），**不重建部件**：选中态、拖拽、淡入动画全部保住；
- 顺带把文件夹弹窗里的成员格（`_member_label_h`）以及无界模式的空位计算
  （`Storage.free_icon_box`）接到同一个字号旋钮上。

## 判据

- 新增 `tests/test_label_fit.py` 21 项：标签带随字号长高、`widget_h <= cell`、真实 `AppIcon`
  在两行 140% 下所有行矩形都在部件内、**3 种格子 × 5 档字号的矩阵**（任何组合都不越界）、
  1.0 倍逐字段零回归、格内居中与 layout 同源、窗口热更新不重建部件 + 三次往返逐字段相等；
- 新增 `tests/test_rename_band.py` 23 项：宽度跟标题带走、四边都在弹窗内（4 成员与 1 成员
  两种弹窗）、贴屏幕边缘时夹进可用区、编辑期间标题隐藏并可恢复（提交/取消两条路径）、
  文字居中 + 加粗 + 输入框自身无边框；
- 全量 **111/111** + smoke，`check_docs` ERROR 0。

## 升级提示

- 无配置迁移；字号调大后格子里的文字会占更高，若某档位装不下两行会自动退回一行（不再裁切）。
- 文件夹弹窗在 140% 字号下会比 100% 高一些（成员格跟着长高），这是刻意的。
